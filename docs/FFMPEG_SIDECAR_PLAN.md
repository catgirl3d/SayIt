# План: FFmpeg sidecar (встроенные FFmpeg/FFprobe)

Дата: 2026-10-16. Статус: интеграция реализована в ветке `feat/ffmpeg-sidecar` (пин+fetch → резолв → bundle/UI → релизный процесс); остались приёмка и merge. После каждого чанка — два независимых код-ревью сторонними агентами (не авторами) до коммита.

Этот документ **меняет прежнее решение о поставке**: на этапе фичи файловой транскрипции было принято «FFmpeg/FFprobe пользователь устанавливает самостоятельно, в установщик не включать». Смена решения обоснована в разделе 1; остальные решения того этапа (контракты, форматы вывода, пайплайн) остаются в силе.

## 1. Зачем это

Три проблемы ручной установки FFmpeg, подтверждённые практикой:

| Проблема | Наблюдение |
| --- | --- |
| PATH-зависимость | Живой баг: SayIt запущен цепочкой процессов со старым снимком PATH; запись `...\ffmpeg-8.1.2-full_build\bin` (без «1») указывала на несуществующую папку — пользователь видел «ffmpeg was not found on PATH» при правильных настройках системы. Windows не перечитывает PATH работающим процессом; пользователь внутри приложения бессилен, кроме ручного выбора папки. |
| Размер ручной установки | Gyan full — 238 МБ архив (8.1.2) / 257 МБ (9.0.2), на диске ~707 МБ (ffmpeg.exe 232 МБ + ffprobe.exe 232 МБ + ffplay.exe 233 МБ). Пользователь скачивает в ~70 раз больше, чем нужно SayIt. |
| Разные сборки у пользователей | Покрытие кодеков зависит от того, что установлено. «Файл не открылся» не воспроизводится и не диагностируется без сбора сведений о чужой сборке. |

Решение: поставлять с приложением фиксированную LGPL-сборку ffmpeg.exe + ffprobe.exe (~7.8 МБ, релиз `v8.1.2-sayit.1`), собранную из проверенного рецепта. Пользователь не ставит ничего и не настраивает PATH.

## 2. Проверенные факты (16.10.2026, рабочая машина)

Проверки выполнены вживую: скачаны сборки, прогнаны точные команды SayIt на тестовом WAV (stereo 48 кГц → mono 16 кГц s16le).

| Проверка | Результат |
| --- | --- |
| AcoustID `audio` (decode-only, 5.74 МБ архив) | Содержит ffmpeg.exe + ffprobe.exe, но **ни одного энкодера и ни одного muxer'а** — для пайплайна SayIt не годится. |
| AcoustID `audio-encode` (7.19 МБ архив, 9.5 МБ распаковано: ffmpeg.exe 4.87 МБ + ffprobe.exe 4.65 МБ) | ffprobe отдаёт ровно поля, которые читает `media.rs`: `codec_name`, `tags`, `disposition.default`, `format.duration`. Демуксеры покрывают все 10 расширений UI. Downmix + ресемплинг работают (та же команда SayIt, `-f wav` вместо `-f s16le`: exit=0, mono 16 кГц s16le, прогресс `out_time_us` пишется; фильтр `aresample` присутствует). |
| Точная команда SayIt на `audio-encode` | **Блокер**: нет muxer'а `s16le` → `Error initializing the muxer for pipe:1`, пустой output. Причина — в их конфиге нет компонента `--enable-muxer=pcm_s16le`. Имя компонента в configure — `pcm_s16le`, отображаемое имя — `s16le`; `--enable-muxer=s16le` configure молча игнорирует. |
| Кодеки `audio-encode` | mp3, aac (LC/HE, ADTS/LATM), alac, ac3, eac3, flac, vorbis, opus, wma v1/v2/pro/lossless/voice, pcm (все), dsd, atrac, gsm, musepack, ape, wavpack, tta, tak, shorten, realaudio. **Нет**: dca (DTS), truehd/mlp. |
| Лицензия | LGPL, без `--enable-gpl`; подходит для поставки sidecar'ом. |
| Контейнеры (демуксеры) | aac, ac3, aiff, alaw/mulaw, ape, asf, au, avi, dsf, flac, flv, matroska/webm, mov/mp4/m4a/3gp, mp3, mpc/mpc8, ogg, rm, shorten, tak, tta, wav, wv, xwma + raw PCM-стримы. |

Источники сборки: репозиторий `acoustid/ffmpeg-build` (рецепт + GitHub Actions, mingw cross-compile), релиз `v8.1.2-1`. Размеры Gyan full подтверждены локально; архив 9.0.2 — 257.7 МБ по Content-Length.

**Собственная сборка и закрепление (форк `catgirl3d/ffmpeg-build`).** Итоговый артефакт — lean-конфиг: decode-вариант + один блок флагов в base-конфиге `common.sh` (commit `f48de538c575f36af723c334330f6d54786d8472`, run 38898544903): `--enable-encoder=pcm_s16le`, `--enable-muxer=pcm_s16le`, `--enable-filter=aresample`, `--enable-decoder=dca/truehd/mlp`. Энкодер в сборке ровно один — `pcm_s16le`; libmp3lame и прочий мёртвый груз отсутствуют. Payload — 7.8 МБ (ffmpeg.exe 4 034 048 Б + ffprobe.exe 3 802 624 Б).

Закреплено релизом **[v8.1.2-sayit.1](https://github.com/catgirl3d/ffmpeg-build/releases/tag/v8.1.2-sayit.1)**: тег указывает на рецепт-коммит `f48de538`; первый релиз опубликован из проверенного run вручную (пересборка по тегу не гарантирует те же байты). В релизе: тарболл, `SHA256SUMS`, `BUILDINFO.txt`.

SHA256:

- архив `ffmpeg-8.1.2-audio-x86_64-w64-mingw32.tar.gz`: `8e9399880364a2e69ef2b7e32ffbacf4d8a8f0d68988ad7af2c4590c816936e3`
- `ffmpeg.exe`: `f16b54c9fb01a5c34a32f0fe62f4ec8a3433c0065605afa944a9bbfe4e5c250b`
- `ffprobe.exe`: `c147e3f92cfdf1005c86cb1a26c3b52a2ae2f410df4f391b8f5110d909051056`

Smoke перед публикацией (точная команда декода SayIt, ожидание ≈64 000 Б, все exit=0): mp3 — 64 000; m4a/aac — 64 644 (+1 %, AAC priming); opus/ogg — 64 000; mkv aac — 64 644; mkv DTS — 64 274; mkv TrueHD — 64 000; wav из папки «Тест папка» с пробелом и кириллицей — 64 000. Сырые `.dts`/`.thd` не открываются (raw-демуксеры не включены) — вне области SayIt: UI принимает mp3/wav/m4a/flac/ogg/mp4/mkv/webm/mov/avi, DTS/TrueHD внутри контейнеров работают.

Целостность закреплённого релиза проверена: скачанный из релиза архив сверен с `SHA256SUMS` (OK), exe после распаковки сверены с хэшами (OK). Настройка immutable release через API для этого репозитория недоступна — целостность обеспечивает пин хэшей в репозитории SayIt (раздел 5).

## 3. Выбранное решение

Sidecar: пара `ffmpeg.exe` + `ffprobe.exe` едет внутри установщика SayIt.

Порядок поиска инструментов (`resolve_tools`):

1. Папка, явно выбранная пользователем (осознанный выбор своей сборки) — оба инструмента обязаны быть в ней, иначе ошибка с именем папки без переключения на встроенные.
2. Встроенная папка sidecar — рабочий путь по умолчанию: release — `resource_dir()/resources/ffmpeg`, debug дополнительно `CARGO_MANIFEST_DIR/resources/ffmpeg`.
3. Если встроенной пары нет — честная ошибка установки («The bundled FFmpeg and FFprobe are missing or damaged. Please reinstall SayIt.»). PATH для файловой транскрипции не используется вообще; оба инструмента резолвятся комплектом из одного каталога.

UI (`FileTranscription.tsx`): блок «Папка FFmpeg (необязательно)» перестал быть про PATH — по умолчанию «Using SayIt's built-in FFmpeg and FFprobe», выбор своей папки остался явным override, кнопка «Use PATH» удалена. Детектор папок (`detect_ffmpeg_directory`) остаётся для пользователей со своей сборкой.

Что НЕ меняется: команды ffmpeg/ffprobe, контракт декода (mono 16 кГц s16le, без seek, прогресс, отмена), форматы вывода, локальный и облачный пути.

## 4. Сборка бинарников

- Рецепт: `acoustid/ffmpeg-build` → форк `catgirl3d/ffmpeg-build`; FFmpeg 8.1.2. Отличие от апстрима — один блок флагов в `common.sh` (base-конфиг, применяется и к decode-варианту): `--enable-encoder=pcm_s16le`, `--enable-muxer=pcm_s16le`, `--enable-filter=aresample`, `--enable-decoder=dca/truehd/mlp`.
- Пиннинг: тег `v8.1.2-sayit.1` + релиз с тарболлом, `SHA256SUMS` и `BUILDINFO.txt`. Первый релиз опубликован из проверенного run вручную (пересборка по тегу может дать другие байты). Обновление FFmpeg = новая сборка, новый тег `v<версия>-sayit.N`, обновление пина в SayIt (раздел 5).
- Бинарники **не коммитить в git**; в SayIt они попадают только через fetch-скрипт по пину.
- Защита fetch-скрипта — пин по SHA-256: архив сверяется до распаковки, оба exe — после; плюс устойчивость к сетевым сбоям (таймаут 120 с, жёсткий лимит 64 МБ с прерыванием потока), санитария архива (по ожидаемому каноническому пути должен оказаться обычный файл — проверка через `stat`), канонизация archive-путей и best-effort уборка staging. Модель угроз инструмента (решение мейнтейнера 16.10.2026): скрипт работает на dev-машине и в CI, локальный атакующий — вне scope; отдельная defense-in-depth машинерия (symlink/reparse/containment/TOCTOU) сознательно не тащится — несовпавшие байты и так отсекаются сверкой хэшей. Офлайн-тесты подключены к `test:scripts`.
- Обновление вручную: раз в квартал-полгода или при CVE в FFmpeg; при выпуске фичи — заметка в `CHANGELOG-FORK.md`.
- Релизный процесс SayIt уже учитывает sidecar: `docs/RELEASE_GUIDE.md`, раздел «FFmpeg sidecar» (шаг fetch в workflow, замена changelog-bullet, критерии приёмки, процедура обновления FFmpeg).

## 5. Интеграция в SayIt

| Участок | Изменение |
| --- | --- |
| `ffmpeg.lock.json` (новый) | Единый пин: версия, URL архива, SHA256 архива и обоих exe, ссылка на BUILDINFO. Читают и fetch-скрипт, и release workflow. Хэш живёт в коммите SayIt — источник истины; скачанное всегда сверяется с ним. |
| fetch-скрипт (новый) | Скачать архив → сверить SHA256 **до** распаковки → распаковать только канонические записи (целостность гарантирует SHA-пин, отдельные fs-эвристики не используются) → проверить оба exe → положить в git-ignored папку перед `tauri build`. Ошибка = стоп сборки; никаких fallback на latest. |
| `client/src-tauri/tauri.conf.json` | Бинарники в bundle через `resources`-map: `resources/ffmpeg/*` → `resources/ffmpeg/` (glob не рекурсивен, поэтому отдельная запись; папку заполняет fetch-скрипт, tracked README держит глоб валидным). `externalBin` отклонён как ненужный. |
| `file_transcription/ffmpeg.rs:51-107` | `program_candidates`/`resolve_tools`: вставить каталог sidecar в порядок поиска (раздел 3). |
| `file_transcription/mod.rs:52,114` | Передача каталога sidecar в `resolve_tools` (через `AppHandle`/`resource_dir`). |

| `test_support.rs` | Юнит-тесты нового порядка резолва (существующие dummy-файлы подходят). |
| CI | Бонус: реальные бинарники становятся доступны в CI — можно добавить e2e с настоящими FFmpeg/FFprobe (ранее фиксировалось как открытый пункт фичи). |

## 6. Лицензии

- Поставляется LGPL-сборка (без `--enable-gpl`), вызывается отдельным процессом — стандартная практика (Buzz, Vibe, whisper-ui).
- Решение мейнтейнера (16.10.2026): source-offer и лицензионные тексты в этой итерации не оформляются — форк для узкого круга. Прослеживаемость обеспечивают `BUILDINFO.txt` (коммит рецепта, run, configure) и `SHA256SUMS` в релизе.
- Замена бинарников пользователем не запрещается (кнопка выбора своей папки остаётся).
- Вопрос вернуть при выходе на широкую публику.

## 7. Что НЕ делаем в этой итерации

- Нативный Rust fast-path (symphonia + rubato) — отдельная тема на будущее; разведка приложена в обсуждении, вердикт: fallback на FFmpeg всё равно нужен, выигрыша по размеру поставки нет.
- MediaInfo вместо ffprobe — не решает декодирование.
- Media Foundation — ограниченное покрытие, сложность, отложено.
- Автоскачивание sidecar при первом запуске — бандл проще и надёжнее.

## 8. Открытые вопросы

- Приёмка: собрать установщик, убедиться, что пара лежит внутри, и что свежая установка на машине без FFmpeg в PATH транскрибирует файл (при первом релизе ветки).
- Измерить фактический прирост установщика (payload пары 7.8 МБ; сжатый NSIS может отличаться) и зафиксировать в release notes.
- Периодичность обновления FFmpeg — ориентир квартал-полгода или CVE; формализовать при первом обновлении.
- Обновление на FFmpeg 9.x — только после повторного полного smoke.

## 9. Критерии готовности

- Чистая Windows без установленного FFmpeg: свежая установка SayIt транскрибирует mp3/wav/m4a/flac/ogg/mp4/mkv/webm/mov/avi без единой настройки.
- Машина со сломанным PATH (кейс из раздела 1): всё работает из sidecar.
- В установщике лежит встроенная пара (payload 7.8 МБ); фактический прирост инсталлятора измерен и зафиксирован в release notes.
- SHA256 пина и скачанного архива сверяются при каждой сборке.
- При выпуске фичи в `CHANGELOG-FORK.md` заменяется существующий bullet секции `v0.2.3 (unreleased)` («File transcription uses FFmpeg and FFprobe that you install yourself…») на формулировку про встроенный FFmpeg — это финальное поведение той же фичи, а не новая запись.
